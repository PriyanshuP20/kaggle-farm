# Scoping: Tape-Solver Agent (the $100k+ architecture)

## What the top agents actually are

Reverse-engineered `lynnsakurai/farmer-john-and-the-idle-seller` (v57, **$180k solo, 0-8 vs our v12**) and traced the lineage upstream through `yhay81/shop-router-0909/0913` (clean 233-line Apache-2.0 base). The entire $100k+ tier shares one architecture:

### Runtime = dumb tape player + router + repair patches

```
observation → pick pre-computed tape by shop-draw → replay tape[step]
                 + repair_weeds / advance_sales / projected_shed / liquidate
```

The "intelligence" is **offline**. The tape is a solved 719-step action script — every `farmer`/`hands[]`/`market[]` op pre-planned — generated by simulating the game ahead of time and **searching over continuations** ("the ten distinct continuations selected in the latest search", per the upstream docstring).

### Routing: first-2-shops → solved continuation

- Shops unlock one per 3 days (`townShopUnlockInterval=3`), drawn with replacement from 8 types, max 8 instances — `rng.choice(seed)`, **deterministic per seed**
- Router reads `unlocked_shops[:2]` at step 144 (day 6) → `SHOP_PLANS` map → picks continuation tape (v57: 64 combos → 41 routes)
- Step 648 (day 27) → switches to the liquidation plan
- v57 adds: rival fingerprinting at step 2 (`_V93_ROUTE_BY_RIVAL`) to pick counter-tapes against known opponents

### Repair layers (why tapes survive live games)

Tapes are built for a canonical scenario; reality diverges. The patches that keep them alive:

| Layer | What it does |
|---|---|
| `repair_weeds` | weed spawned on a PLANT/BUILD tile → insert DIG, replay the op next turn (same-day queue, expires at dawn) |
| `advance_sales` | sell *next* turn's planned SELLs now if the price is good — rides transient spikes |
| `subtract_advanced_sales` | don't double-sell what was already advanced |
| `projected_shed` | simulate this turn's PICKUP/DROP/PLACE to estimate shed before committing orders |
| `liquidate` | step 718: dump entire projected shed, price-sorted |
| `front_run` (v57) | read the *opponent's* scheduled SELL and sell first — captures pre-crash price |
| `budget_guard` / `room_guard` / `clamp_sells` / `dead_stock` | shed-cap + shortfall + stale-stock safety |

## Why the game is tape-solvable

**Fully deterministic per seed.** Shops (`rng.choice(seed)`), weeds (`rng(seed*1000003)^day`, `weedSpawnChance=0.005`), market price curves — all seeded. Given a seed, the whole episode is fixed before it starts. On Kaggle the seed is hidden, so agents route on the *observable* shop draw and patch the rest.

## The hard part: generating the tapes

The tape is the product. Three generation methods, in order of sophistication:

### A. Record-replay (proven, ~$60-70k ceiling)
Run our reactive agent against a fixed shop draw, record `tape[step]`. **Verified working** — recorded v12 seed-0 → replayed → identical $53,884. The tape is only as good as the agent that made it, but it's a valid starting library.

### B. Local search on the tape (the "continuations" method — likely what upstream does)
Take a recorded tape → mutate macro-decisions (hire timing, buy counts, sell schedules, crop mix) → re-simulate → keep improvements. The search space is the *plan structure*, not raw ops. Feasible at ~4s/sim, ~15 sims/min parallel; needs ~50-200 evals per draw × 64 draws — hours-days of compute.

### C. Structured planner (full solve)
Hand-build a scheduler that emits the optimal line directly per draw. Highest ceiling, biggest effort — essentially writing a game solver.

## The brittleness problem (and why patches exist)

A tape assumes a market environment. The shared market is the divergence source: a strong opponent floods the same curves the tape was optimized for. That's what `front_run`/`sell_lead`/`clamp_sells` are for. **A pure tape with no patches loses to a reactive agent that actively competes** — v57's patches are what let it hold $150k+ against live opponents.

## Recommended path

**Phase 1 — per-draw tuned reactive agent** (captures ~80% of the value, days not weeks):
- We already have `KAG_PARAMS` + `tune.py` + shop-draw detection
- Group local seeds by first-2-shop draw; tune `KAG_PARAMS` per draw-class (milk-heavy → more cows; yarn → sheep; egg shops → geese; melon-hostile → diversify)
- At runtime: day 6 → read `unlocked_shops[:2]` → `os.environ`-style params lookup → reactive agent plays the tuned profile
- **Robust to weeds/opponent by construction** — no tape brittleness

**Phase 2 — tape opening + reactive continuation** (hybrid):
- Script the optimal opening (days 0-6: hire/seeds/structures/first buys are ~identical regardless of draw) as a tape
- Day 6+: reactive agent continues with the draw-matched params
- Captures the ramp-speed edge without the full-solver build

**Phase 3 — full tape library** (if 1-2 prove insufficient):
- Record winning reactive runs per draw → local-search the continuations → embed tape library + router + repair layers
